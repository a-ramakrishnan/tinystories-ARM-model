    Step 2

    Turn text into tokens

    Models read numbers, not letters. The GPT-2 tokenizer splits text into tokens and maps each one to an ID from a vocabulary of 50,257.

    How tokenization works

    Explained
    Byte-pair encoding (BPE). The vocabulary was built by starting from single bytes and repeatedly merging the most common pairs. Frequent words end up as one token; rare words are spelled out in pieces.
    Spaces belong to the next word. " upon" (with its space) is a different token from "upon". That's why most tokens start with ·.
    About 4 characters per token in English. Fewer tokens means the model sees more text in its context window and trains faster.

    Step 3

    Cut training batches

    The model learns one thing: given some tokens, predict the next one. Batches turn the token stream into lots of those little exercises at once.

    A worked example

    Explained

    With a context window of 6 tokens, one window of the sentence below becomes these training examples:

    Input and target. The target is the input shifted one token to the left. So one window of block_size tokens holds block_size examples, each with a longer context.
    Random windows. Each window starts at a random place in train.bin, so every batch is different and a window can cross from one document into the next.
    A batch is a stack. batch_size windows are processed in parallel on the GPU. 32 windows × 128 tokens = 4,096 next-token predictions per step.

    Step 6

    Train

    Each step: predict the next token at every position of a batch, measure how wrong that was, and nudge every parameter to be a little less wrong.

    What one training step does

    Explained
    1. Forward pass. The batch goes through the model, which gives a probability for every possible next token at every position.
    2. Loss. For each position, take the probability the model gave the correct next token and compute −ln(p); the loss is the average. See the examples below.
    3. Backward pass. PyTorch works out, for every parameter, which direction would lower the loss (the gradient).
    4. Update. Every gradient_accumulation_steps steps, AdamW moves all parameters a little in that direction. The size of the move is the learning rate.
    Model gives the right tokenLossPerplexity

    Perplexity = eloss: the model is as unsure as if it were choosing among that many equally likely tokens.

    Learning rate over this run

    Linear warmup avoids wild early updates; the cosine decay makes the last updates small and careful.

Continuing with the same number of steps finishes an interrupted run exactly as if it had never stopped. Asking for more steps extends a finished run: the learning-rate schedule is stretched to the new end, and the learning rate ramps back up from where it stopped over a short re-warmup, so the model keeps learning instead of crawling at the minimum learning rate.

    Trained model: parametersHow is this calculated?
    Presets (Balanced is the default)
    What do these do?
    • Temperature sharpens (below 1) or flattens (above 1) the model's probabilities before picking. At 0 it's greedy: always the single most likely token, so the same prompt always gives the same text.
    • Top-k keeps only the k most likely tokens (0 = off).
    • Top-p (nucleus sampling) keeps the smallest set of tokens whose probabilities add up to p. When the model is sure, that's a few tokens; when it's unsure, many (1 = off).
    • Min-p drops tokens less likely than min-p × the top token's probability, so the cut-off follows the model's confidence (0 = off).
    • Repetition penalty makes every token already in the context less likely (divides its score by the penalty). Frequency penalty grows with how many times a token has appeared; presence penalty is a flat cost for appearing at all. They're applied first, then temperature, top-k, top-p and min-p.
    • Typical-p (locally typical sampling) keeps the tokens whose surprise is closest to the model's average surprise at this point, up to p of the probability: it drops the blandest choices as well as the unlikely ones (1 = off).
    • DRY ("don't repeat yourself") penalizes only tokens that would continue a sequence already in the text, more the longer the repeat would get; single words can come back freely. It stops greedy decoding from looping without making it random (0 = off).

    Time per token

    What happens during inference

    1. Prefill. The prompt's tokens go through the model in one pass. That, plus picking the first token, is the time to first token.
    2. Decode. Each new token needs one more pass. With the KV cache, every layer keeps the keys and values it already computed, so only the new token is processed. Without it, the whole context is re-read every time.
    3. Sliding window. Past 128 tokens, only the most recent fit in the context window. This model's positions are learned per slot, so when the window slides the cache must be rebuilt ("recomputes").

    Other ways to generate

    Decoder inference

    Contrastive search is deterministic like greedy but doesn't loop: of the k most likely tokens it prefers the one least like anything already written. Beam search keeps the most probable few continuations at every step (optionally never repeating a 3-token sequence). Several samples at once draws many continuations in one batch, almost as fast as one, using the temperature, top-k and top-p above (penalties aren't applied).

    How the KV cache works

    Decoder inference

    Every layer turns each token into a key (what this token offers to later tokens) and a value (what it passes on when attended to). A new token's query is compared with the keys of every earlier token. Those keys and values never change, so they can be kept instead of recomputed.

    KV cache memory

    2 × layers × KV width × bytes × tokens × sequences

    The tests

    How a model takes a multiple-choice test

    The model never writes an answer. For each option, it reads the question followed by that option and adds up the log-probabilities of the option's tokens: how natural it finds that continuation. The option it finds most likely is its answer (accuracy). Longer options have more tokens and so lower totals, so length-normalized accuracy divides by the option's length first. LAMBADA is different: the model must produce the passage's last word itself (greedy), and its perplexity on the right word shows how close it came.

    At this size, scores sit close to chance, and a gain of a point or two is real only if it's larger than the ± (one standard error) shown with each result.
